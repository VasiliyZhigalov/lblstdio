# КРУПНЫЙ ПЛАН РЕАЛИЗАЦИИ (ROADMAP)
## Платформа активного обучения и полуавтоматической разметки «Roboflow-Lite»

План разбит на **6 последовательных фаз**. Каждая фаза завершается созданием работающего инкремента системы (Milestone), который можно протестировать независимо от последующих шагов.

### ФАЗА 1. Каркас системы и базовая ручная разметка (Core MVP)
**Цель:** Получить работоспособное локальное веб-приложение: загрузка файлов $\to$ ручное рисование прямоугольников $\to$ сохранение в SQLite $\to$ ручной экспорт в архив YOLO.

* **Backend:**
  * Развертывание скелета Чистой архитектуры (Domain, Application, Infrastructure, Presentation).
  * Настройка асинхронного SQLite (`aiosqlite`) и локального файлового хранилища (`./storage`).
  * CRUD для проектов и справочника классов (с фиксацией HEX-цветов и `index_id`).
  * Пакетный загрузчик изображений с автоматическим делением на Train/Valid/Test.
  * Базовые эндпоинты сохранения/чтения аннотаций кадра.
* **Frontend:**
  * Каркас на чистом JS (ES-модули) и Tailwind CSS: галерея изображений + экран разметчика.
  * Реализация холста (Canvas): отображение картинки, Zoom к курсору, Pan (сдвиг).
  * Инструмент создания рамок (Drag-to-create), изменение размера через 8 точек, перемещение.
  * Горячие клавиши: `W` (бокс), `V` (курсор), `A`/`D` (навигация с автосохранением), `1–9` (классы), `Del`.
* **Результат этапа (Milestone 1):** Пользователь может загрузить 30 картинок, вручную разметить их боксами без лагов и скачать валидный YOLO-архив с `data.yaml`.

### ФАЗА 2. Полуавтоматический перенос через точки (Keypoint Matching)
**Цель:** Ускорить разметку серийных и похожих кадров через сопоставление особых точек без участия нейросетей детекции.

* **Backend:**
  * Интеграция модуля сопоставления точек (OpenCV SIFT или связка SuperPoint + LightGlue).
  * Сценарий `PropagateBoxViaKeypoints`: кроп исходного бокса $\to$ поиск соответствий $\to$ RANSAC/гомография $\to$ проекция рамки на целевой кадр.
  * Введение доменного инварианта: спроецированная рамка создается строго со статусом `source = KEYPOINT_PROPAGATION` и `verification_status = PENDING_REVIEW`.
* **Frontend:**
  * Буфер обмена: копирование рамки (`Ctrl+C`) на кадре А $\to$ вставка с сопоставлением (`Ctrl+Shift+V`) на кадре Б.
  * Визуальное разделение рамок на холсте: проверенные — сплошные, перенесенные — пунктирные с предупреждающей плашкой.
  * Локальные всплывающие кнопки над рамкой: «Подтвердить» / «Удалить».
* **Результат этапа (Milestone 2):** Разметчик копирует объект с одного кадра, вставляет на другой с автоматической подгонкой геометрии и подтверждает результат за 1 клик.

### ФАЗА 3. Версионирование датасетов и Human-in-the-Loop шлюз
**Цель:** Реализовать неизменяемые снимки данных (снапшоты) и жестко заблокировать попадание непроверенных данных в обучающую выборку.

* **Backend:**
  * Сущности `DatasetVersion`, `DatasetItem` и `AugmentationConfig`.
  * **HITL-шлюз (Security Gate):** логика проверки, запрещающая сборку версии датасета, если хотя бы один бокс имеет статус `PENDING_REVIEW`.
  * Пайплайн подготовки данных: приведение к 640x640, генерация аугментаций (Albumentations: флипы, яркость, контраст, сдвиги) только для проверенного Train-сплита.
  * Фиксация версий в виде готовых изолированных папок на диске.
* **Frontend:**
  * Модальное окно «Создать версию датасета» с выбором параметров аугментации.
  * Блокировка кнопки сборки с подсказкой: «В датасете есть N неподтвержденных объектов. Завершите проверку».
* **Результат этапа (Milestone 3):** Платформа умеет генерировать фиксированные версионированные датасеты (`v1`, `v2`), на 100% гарантируя чистоту и валидность разметки человеком.

### ФАЗА 4. Обучение YOLOv8n и цикл авторазметки (Active Learning Core)
**Цель:** Замкнуть внутренний цикл: Обучение модели $\to$ Пакетная авторазметка $\to$ Быстрая приемка человеком $\to$ Дообучение.

* **Backend:**
  * Интеграция `ultralytics`: запуск `YOLO('yolov8n.pt').train()` в отдельном системном процессе/потоке.
  * Перехват метрик по эпохам (loss, mAP50, mAP50-95) и сохранение в историю задачи `TrainingJob`.
  * Реестр обученных моделей `ModelVersion` с привязкой к версии датасета и сохраненным весам `best.pt`.
  * Фоновый сценарий пакетного инференса (`BatchAutoLabel`): прогон неразмеченных картинок с генерацией предсказаний в статусе `PENDING_REVIEW`.
* **Frontend:**
  * Экран / шторка мониторинга обучения модели с графиком лосса в реальном времени.
  * Интерфейс пакетного запуска авторазметки с ползунком порога уверенности (Confidence Threshold).
  * **Режим экспресс-верификации (Review Bar):** панель внизу экрана с кнопками «Подтвердить все (Space)» и «Отклонить (R)» для мгновенной приемки предсказаний нейросети.
* **Результат этапа (Milestone 4):** Замкнутый цикл активного обучения: обучили `Model v1` на 30–50 кадрах $\to$ автоматически разметили следующие 100 кадров $\to$ человек пробелом подтвердил верные рамки $\to$ собрали `Dataset v2` $\to$ запустили обучение `Model v2`.

### ФАЗА 5. Захват потока и отбор по неуверенности (Stream & Uncertainty Sampling)
**Цель:** Подключить источник «живых» данных (RTSP-камера/видео) и автоматически отбирать в очередь разметки только сложные пограничные кадры.

* **Backend:**
  * Фоновый сервис-демон чтения видеопотока через OpenCV (`VideoCapture`).
  * Real-time инференс кадров на последней активной модели проекта с пониженным FPS (1–2 кадра/сек).
  * **Алгоритм Uncertainty Sampling:** отбор кадра только при наличии детекций в окне неопределенности (например, $0.70 \le \text{conf} \le 0.90$).
  * Cooldown-фильтр (защита от сохранения одинаковых кадров подряд).
  * Автоматическое сохранение отобранного кадра в базу со статусом `REQUIRES_REVIEW` и привязкой предварительных рамок.
* **Frontend:**
  * Модальное окно управления стримом (ввод RTSP-ссылки, настройка диапазона уверенности, кнопка Старт/Стоп).
  * Бейдж-индикатор в шапке: «Поток активен / Захвачено новых кадров: N».
  * Быстрый переход к проверке кадров, поступивших со стрима.
* **Результат этапа (Milestone 5):** Камера работает в реальном времени; система игнорирует тривиальные сцены и автоматически подсовывает человеку на проверку только те кадры, где модель сомневается.

### ФАЗА 6. Оптимизация, полировка UX и интеграционное тестирование
**Цель:** Довести приложение до высокой скорости отклика, отсутствия утечек памяти при обучении и удобства непрерывной работы разметчика.

* **Задачи оптимизации:**
  * Проверка утечек памяти CUDA / RAM при многократных перезапусках обучения и инференса Ultralytics.
  * Виртуализация / пагинация списка изображений в галерее (чтобы интерфейс не падал на 5 000+ кадрах).
  * Стресс-тестирование холста на тяжелых 4K-изображениях: кеширование отрисовки рамок, отзывчивый Zoom/Pan.
  * Полировка «слепого» клавиатурного управления (разметка 50 кадров подряд без использования мыши).
* **Интеграционный тест всего пайплайна (End-to-End):**
  1. Загрузка 30 кадров $\to$ ручная разметка + LightGlue.
  2. Сборка `Dataset v1` $\to$ Обучение `Model v1`.
  3. Подключение видео $\to$ Сбор 50 сложных кадров через Uncertainty Filter.
  4. Экспресс-верификация через `Space` $\to$ Сборка `Dataset v2` $\to$ Обучение `Model v2`.
  5. Сравнение метрик: подтверждение роста mAP между версиями v1 и v2.
* **Результат этапа (Milestone 6):** Стабильный автономный инструмент, готовый к решению прикладных задач детекции объектов.
