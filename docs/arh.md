# КОНЦЕПТУАЛЬНЫЙ АРХИТЕКТУРНЫЙ ДОКУМЕНТ
## Интеллектуальная платформа полуавтоматической разметки и активного дообучения (Active Learning CV Platform)

---

## 1. Общая концепция системы

В основе системы лежит парадигма **Active Learning (Активное обучение)** и **Human-in-the-Loop (HITL)**. 

Вместо монотонной ручной разметки сотен изображений платформа реализует **циклический самоускоряющийся процесс (Data Flywheel)**:
1. Человек размечает минимальное опорное ядро данных (30–50 кадров) вручную и с помощью полуавтоматического переноса боксов через сопоставление особых точек (Keypoint Matching).
2. На этом ядре обучается первая итерация легкой нейросети (YOLOv8n).
3. Модель размечает следующий пул данных.
4. Человек выступает в роли верификатора: исправляет ошибки и подтверждает правильные боксы (что в 5–10 раз быстрее разметки с нуля).
5. Модель переобучается на расширенном датасете.
6. Модуль потокового видео в реальном времени отбирает из внешней среды только те кадры, в которых модель «сомневается», и автоматически пополняет ими пул для разметки.

```
       ┌────────────────────────────────────────────────────────┐
       │   1. Загрузка данных / Внешний стрим (RTSP/Видео)      │
       └───────────────────────────┬────────────────────────────┘
                                   │
                                   ▼
       ┌────────────────────────────────────────────────────────┐
       │   2. Разметка ядра: Вручную + Keypoint Propagation     │
       └───────────────────────────┬────────────────────────────┘
                                   │
                                   ▼
 ┌───► ┌────────────────────────────────────────────────────────┐
 │     │   3. Сборка версии датасета + Аугментации              │
 │     └───────────────────────────┬────────────────────────────┘
 │                                 │
 │                                 ▼
 │     ┌────────────────────────────────────────────────────────┐
 │     │   4. Обучение модели (YOLOv8n)                         │
 │     └───────────────────────────┬────────────────────────────┘
 │                                 │
 │                                 ▼
 │     ┌────────────────────────────────────────────────────────┐ ◄── Новые кадры
 │     │   5. Авторазметка пула с фильтром по уверенности       │     со стрима
 │     └───────────────────────────┬────────────────────────────┘
 │                                 │
 │                                 ▼
 │     ┌────────────────────────────────────────────────────────┐
 │     │   6. Верификация человеком (Approve / Reject / Edit)   │
 │     └───────────────────────────┬────────────────────────────┘
 │                                 │
 └─────── [Повторять цикл до достижения целевых метрик] ────────┘
```

## 2. Сквозной пользовательский процесс (End-to-End Workflow)

### Этап 1: Импорт данных
* **Сценарий А (С нуля):** Загрузка папки с «сырыми» фотографиями без разметки.
* **Сценарий Б (С готовой базой):** Загрузка архива с разметкой (YOLO `.txt` или COCO `.json`). Система связывает картинки с уже имеющимися классами и координатами.

---

### Этап 2: Ручная разметка стартового ядра
* Разметчик берет первые 10–20 изображений и размечает объекты целевых классов классическими прямоугольниками (Bounding Boxes).
* Создается минимальный пул «эталонных» объектов для каждого класса.

---

### Этап 3: Перенос разметки через сопоставление точек (Keypoint Box Propagation)
Механизм предназначен для быстрого переноса разметки между похожими кадрами (один и тот же объект под разными углами, перемещение объекта в кадре, смена масштаба).

#### Логика работы (UI/UX):
1. Разметчик находится на Изображении А, где объект уже выделен боксом.
2. Пользователь нажимает на бокс и выбирает действие **«Копировать для сопоставления» (`Ctrl + C`)**.
3. Пользователь переходит на похожее неразмеченное Изображение Б и нажимает **«Вставить через ключевые точки» (`Ctrl + Shift + V`)**.

#### Логика работы алгоритма (Backend):
1. **Экстракция признаков:** Модели детекции ключевых точек (SIFT, ORB либо нейросетевые SuperPoint / DISK) извлекают дескрипторы точек внутри выделенного бокса на Изображении А и на всем Изображении Б.
2. **Матчинг (Matching):** Алгоритм LightGlue (или классический FLANN/BFMatcher) сопоставляет пары точек между боксом кадра А и пространством кадра Б.
3. **Оценка геометрической трансформации:**
   * С помощью алгоритма RANSAC отсеиваются выбросы (ложные сопоставления).
   * Вычисляется матрица аффинного преобразования или гомографии ($H$).
4. **Проекция бокса:** Вершины исходного прямоугольника умножаются на матрицу трансформации. Вычисляется охватывающий прямоугольник (Axis-Aligned Bounding Box) на Изображении Б.
5. **Результат:** На Изображении Б появляется спроецированный бокс с присвоенным классом. Разметчик при необходимости подправляет границы за 1 секунду вместо рисования с нуля.

---

### Этап 4: Версионирование датасета, аугментации и обучение
Когда набрано критическое число подтвержденных объектов (например, 30–50 кадров):

1. **Создание Snapshot (Версии):**
   * Все кадры со статусом «Подтверждено» фиксируются в неизменяемый срез (например, `Dataset v1`).
   * Данные разделяются на выборки: Train (70%), Valid (20%), Test (10%).
2. **Пайплайн препроцессинга и аугментации:**
   * Приведение к единому разрешению (Resize: 640x640 с сохранением пропорций и добавлением полей / Letterbox).
   * Генерация аугментированных копий для выборки Train (Flips, Random Crop, изменения яркости/контраста, сдвиги). Датасет увеличивается в 2–3 раза.
3. **Фоновое обучение (Training Worker):**
   * Система запускает асинхронную задачу обучения сверхлегкой модели **YOLOv8n (nano)** (быстрый старт на CPU/GPU, обычно 20–50 эпох).
   * В интерфейсе отображается статус обучения, график лосса и метрики (mAP@50).
   * По завершении обученные веса (`best.pt`) регистрируются в реестре моделей проекта как `Model v1`.

---

### Этап 5: Авторазметка пула изображений (Model-Assisted Labeling)
1. Пользователь выбирает пакет оставшихся неразмеченных картинок (например, следующие 100 кадров).
2. Выбирается обученная модель (`Model v1`) и задается **порог уверенности (Confidence Threshold)**:
   * Например: детектировать только объекты с уверенностью $\ge 0.50$.
3. Модель в фоновом режиме прогоняет инференс по неразмеченному пулу.
4. Найденные предсказания записываются в базу данных для каждого кадра со специальным статусом: **`Predicted` (Предсказано нейросетью)**.
5. В интерфейсе такие рамки подсвечиваются пунктирной линией, а рядом с меткой класса отображается процент уверенности модели (например, `car 0.84`).

---

### Этап 6: Режим быстрой верификации человеком (Review Workflow)
Интерфейс переходит в режим экспресс-приемки. Разметчику не нужно чертить рамки:
* **Подтвердить (`Y` / `Space`):** Все предсказания нейросети на кадре считаются верными. Статус меняется на `Approved`. Пунктир становится сплошным. Переход к следующему кадру.
* **Исправить (`V` / Drag):** Разметчик быстро подтягивает край криво вставшего бокса или удаляет ложное срабатывание (`Del`).
* **Доразметить (`W`):** Если модель пропустила неочевидный объект, человек вручную добавляет один бокс.
* **Отклонить (`R`):** Полная очистка предсказаний на кадре, если модель ошиблась кардинально.

*Скорость обработки возрастает в 5–10 раз по сравнению с ручным трудом.*

---

### Этап 7: Итеративное активное дообучение (Active Learning Loop)
* Повторяются шаги 4–6:
  * Создается `Dataset v2` (уже включает 150 кадров: 50 из v1 + 100 проверенных из авторазметки).
  * Обучается `Model v2`. Ее качество (mAP) выше, так как объем и вариативность данных выросли.
  * `Model v2` применяется для разметки следующих 200–500 изображений.
* Цикл продолжается до тех пор, пока точность модели не выйдет на плато, а разметчик перестанет исправлять ошибки модели, лишь нажимая «Подтвердить».

---

### Этап 8: Потоковый модуль сэмплирования неуверенности (Stream Ingestion & Uncertainty Sampling)
Модуль решает проблему: **«Как автоматически отбирать из бесконечного видеопотока только полезные для обучения кадры?»**.

#### Архитектура модуля:
1. **Видеопоток:** Подключение по RTSP, захват с вебкамеры или непрерывный разбор длинного видеофайла.
2. **Real-time инференс:** Стрим пропускается через последнюю рабочую версию модели (`Model vN`) с частотой 2–5 кадров в секунду (FPS sampling).
3. **Фильтр неопределенности (Uncertainty Sampling):**
   * Кадры, где модель **абсолютно уверена** (все объекты имеют `conf > 0.90`), **отбрасываются** (они не научат модель ничему новому).
   * Кадры, где модель **ничего не видит** (или `conf < 0.30`), чаще всего содержат шум или пустой фон (их сбор строго лимитируется).
   * **Зона интереса (Uncertainty Window):** Если на кадре обнаружен хотя бы один объект с уверенностью в диапазоне **0.60 – 0.85** (настраиваемый интервал), модель «колеблется». Именно такие кадры несут максимальный информационный выигрыш.
4. **Защита от дублей (Deduplication):** Если поток статичен, система не должна сохранять 100 одинаковых кадров подряд. Вводится порог задержки (Cooldown, например, не чаще 1 кадра в 3 секунды для одного класса).
5. **Доставка в очередь разметки:**
   * Отобранный кадр автоматически сохраняется в локальное хранилище.
   * На кадр сразу накладываются предсказанные моделью «сомнительные» боксы.
   * Кадру присваивается статус `Stream: Needs Review`, и он отправляется в самое начало очереди на проверку человеку.

## 3. Модель жизненного цикла изображения (State Machine)

Каждое изображение в системе находится в одном из строго определенных состояний:

```
                  ┌──────────────────────────────────────────────┐
                  │                  RAW_UPLOAD                  │
                  └──────────────┬───────────────────────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 │ Разметка вручную / LightGlue  │ Запуск инференса модели
                 ▼                               ▼
  ┌──────────────────────────────┐ ┌──────────────────────────────┐
  │       MANUAL_ANNOTATED       │ │        AUTO_PREDICTED        │
  └──────────────┬───────────────┘ └──────────────┬───────────────┘
                 │                                │
                 │                 ┌──────────────┴──────────────┐
                 │                 │ Человек подтверждает/правит │
                 │                 ▼                             ▼
                 │        ┌──────────────────┐          ┌──────────────────┐
                 │        │     APPROVED     │          │     REJECTED     │
                 │        └────────┬─────────┘          └──────────────────┘
                 │                 │
                 └────────┬────────┘
                          ▼
             ┌──────────────────────────────┐
             │       INCLUDED_IN_DATASET    │ ──► [Входит в Snapshot vX]
             └──────────────────────────────┘
```

## 4. Архитектурные подсистемы приложения

Приложение разделяется на 4 независимых функциональных блока:

### 4.1. Core Application (Основное веб-приложение)
* **API и интерфейс разметки:** Отображение галереи, холст Konva.js, ручное редактирование рамок, управление классами.
* **Storage Provider:** Локальная файловая структура и база данных SQLite для хранения координат, статусов и истории версий.

### 4.2. Geometric Matching Engine (Модуль переноса разметки)
* Локальный сервис/класс, инкапсулирующий OpenCV и нейросетевые экстракторы признаков (LightGlue/SuperPoint или SIFT).
* Работает синхронно или через быстрый RPC: принимает координаты бокса на изображении А и буфер изображения Б, возвращает спроецированный бокс на изображении Б.

### 4.3. ML Training & Inference Worker (Фоновый воркер машинного обучения)
* Очередь задач (Task Queue), изолированная от основного веб-сервера (чтобы обучение модели не блокировало пользовательский интерфейс).
* **Задачи воркера:**
  * Генерация аугментированного датасета по правилам версионирования.
  * Запуск процесса обучения `ultralytics YOLO` с логированием эпох в базу данных.
  * Пакетный инференс по массиву неразмеченных изображений.

### 4.4. Stream Listener & Active Learning Sampler (Модуль видеопотока)
* Независимый фоновый сервис (демон).
* Подключается к видеопотоку (RTSP/Webcam/File).
* Выполняет легковесный инференс каждого $N$-го кадра через текущую активную модель.
* Проверяет математическое условие попадания в окно неопределенности:
  $$\exists \, b \in \text{Boxes} : \text{Conf}_{min} \le \text{Confidence}(b) \le \text{Conf}_{max}$$
* В случае выполнения условия и прохождения фильтра дубликатов — отправляет кадр через внутренний API в Core Application со статусом `Stream: Needs Review`.

## 5. Преимущества концепции

1. **Экономия времени до 80%:** Ручная разметка требуется только для первых 30–50 изображений. Вся дальнейшая работа сводится к верификации (клики «Да / Нет») и переносу через Keypoints.
2. **Качественный рост датасета (Data-Centric AI):** Модуль стриминга не раздувает базу гигабайтами бесполезных одинаковых фотографий, а находит исключительно редкие, сложные и пограничные ситуации, на которых модель ошибается.
3. **Автономность:** Полный цикл от сырых изображений до готовой обученной модели запускается локально без необходимости использования внешних облачных сервисов.
