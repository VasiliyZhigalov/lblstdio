# Автоматическая верификация авторазметки по устойчивости к аугментациям

## Цель

После обычной авторазметки автоматически подтверждать изображение только тогда,
когда детекции сохраняются при нескольких безопасных преобразованиях изображения.
Такие изображения получают статус `AUTO_VERIFIED` и могут попасть в датасет без
ручного подтверждения. Пустые результаты автоматически не подтверждаются.

## Согласованные правила

Для каждого изображения выполняются три инференса одной и той же модели:

1. исходное изображение;
2. горизонтально отражённое изображение;
3. слегка масштабированное/растянутое изображение.

Боксы результатов преобразованных прогонов возвращаются в исходную систему
координат. Изображение считается устойчивым, если:

- каждый из трёх прогонов содержит одинаковое ненулевое количество боксов;
- для каждого сопоставленного бокса совпадает класс;
- confidence каждого бокса не ниже порога авторазметки;
- IoU сопоставленных боксов после обратного преобразования не ниже `0.8`.

Если хотя бы одно условие нарушено, изображение остаётся
`REQUIRES_REVIEW`, а его модельные аннотации остаются `PENDING_REVIEW`.

## Архитектура

`BatchAutoLabelUseCase` сохраняет обычные предсказания и запускает отдельный
доменный/application-сервис проверки согласованности. Сервис не зависит от
Ultralytics и работает через существующий `IModelPredictor`.

Проверка не сохраняет все промежуточные прогоны в БД. Сохраняется только
результат через статусы:

- `ImageStatus.AUTO_VERIFIED`;
- `VerificationStatus.AUTO_VERIFIED` для модельных аннотаций.

Использование отдельного статуса аннотаций необходимо, чтобы автоматическое
подтверждение не выглядело как действие человека и при этом могло участвовать
в сборке датасета.

## Изменения доменной модели

- Добавить `AUTO_VERIFIED` в `ImageStatus` и `VerificationStatus`.
- `Image.recalculate_status()` учитывать автоматически подтверждённые аннотации.
- `Image.can_be_included_in_dataset()` разрешить `VERIFIED` и `AUTO_VERIFIED`.
- `Annotation.is_exportable` разрешить `VERIFIED` и `AUTO_VERIFIED`.
- Сборщик датасета принимать изображения и аннотации с обоими подтверждёнными
  статусами.
- Ручное редактирование или отклонение автоматически подтверждённой аннотации
  должно продолжать работать по существующему workflow.

## Проверка преобразований

Проверка геометрии будет изолирована в небольших чистых функциях:

- преобразование нормализованного бокса при отражении/масштабировании;
- обратное преобразование бокса;
- вычисление IoU;
- сопоставление боксов по классу и геометрической близости;
- агрегированная проверка количества, confidence и IoU.

Преобразованные изображения создаются во временной директории и не попадают в
хранилище проекта. Путь к весам и исходные пути изображений передаются
предиктору через существующий порт.

## Параметры

- порог confidence берётся из `AutoLabelJob.confidence_threshold`;
- порог IoU устойчивости добавляется в job со значением по умолчанию `0.8`;
- существующий `iou_threshold` авторазметки остаётся параметром NMS модели и не
  используется как порог геометрической устойчивости.

## Ошибки и отказоустойчивость

Если дополнительный инференс или подготовка временного изображения завершается
ошибкой, job получает статус `FAILED`, как и при ошибке обычной авторазметки.
Частично подтверждённые изображения не сохраняются: статус и аннотации
изменяются атомарно в рамках текущего unit of work.

## API и UI

Запрос авторазметки получает опциональный параметр порога устойчивости с
default `0.8`. Ответ job сохраняет этот параметр. Существующие API чтения
изображений и аннотаций уже передают строковые статусы, поэтому отдельный
контракт для чтения не требуется. UI сможет отображать `AUTO_VERIFIED` отдельно
после обновления визуальных меток, но это не блокирует backend MVP.

## Тестирование

Нужны:

- unit-тесты преобразований боксов и IoU;
- unit-тесты успешной проверки устойчивого набора;
- unit-тесты отказа при разном количестве боксов, классе, confidence, IoU и
  пустом результате;
- unit-тест интеграции batch auto-label с дополнительными прогонами;
- unit-тесты доменных статусов и допуска `AUTO_VERIFIED` в сборку датасета;
- regression-тест, подтверждающий, что обычная неустойчивая авторазметка остаётся
  `PENDING_REVIEW`.
